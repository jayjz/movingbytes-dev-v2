Unhinged Agent

A thin-client, private voice assistant. ESP32-S3 edge hardware streamed via WebSocket to an RTX 4060 host for local STT, LLM inference, and TTS orchestration.

Phase 1 PoC · Digital Twin Complete

The Problem

Cloud voice assistants represent a massive privacy compromise and fail entirely in dead zones. Moving inference locally solves privacy, but consumer edge devices lack the memory to run modern LLMs or fast Text-to-Speech (TTS).

Furthermore, standard voice bots suffer from terrible UX: they cannot be interrupted without breaking their internal logic state. We needed an architecture that separates the audio interface from the heavy compute, with a rigorous state machine to handle human interruptions.

Architecture Decisions

1. Edge/Host Split — The ESP32-S3 acts purely as an audio conduit. It handles wake-word detection and streams raw audio over WebSockets. A local RTX 4060 host catches the stream, runs Whisper.cpp for transcription, processes the LLM response, and streams audio back.

2. The Barge-in FSM — Interruptibility is treated as a first-class system requirement. A strict Finite State Machine governs the audio pipeline. If the wake-word is detected while the system is in the SPEAKING state, it instantly truncates the playback buffer and transitions to LISTENING without leaking context.

Business Impact & JTBD

Absolute Data Sovereignty. By air-gapping the audio processing from the cloud, this architecture is viable for legal, medical, or highly sensitive corporate environments where data leakage is a non-starter.

Beyond privacy, this eliminates recurring API costs for Speech-to-Text and token generation, shifting the business model from operating expense (OpEx) to fixed capital expense (CapEx).

class AudioState(Enum):
    IDLE = auto()
    LISTENING = auto()
    PROCESSING = auto()
    SPEAKING = auto()

class BargeInFSM:
    def __init__(self):
        self.state = AudioState.IDLE
        self.audio_buffer = []

Trade-offs & Decisions

Accepted

ESP32 over Raspberry Pi

We sacrificed the ease of running Python on the edge to use an ESP32. This drastically lowers power consumption and unit cost, forcing all heavy logic to the central host.

Deferred

Physical Hardware Integration

The logic is verified against a browser-based WebSocket digital twin. Deployment to the physical ESP32-S3-BOX-3B is pending.
