## Design brief

Audience: an experienced engineer assessing control-plane reasoning. Enable a quick understanding of why a strategy request is admitted or rejected under constrained compute. One direction: Observatory Ledger typography, an open ruled surface, request → dominant gate → exact decision. No new visual family, imagery, dependencies or telemetry.

Four cases hold the balanced → high_fidelity request and 100-token context constant; change expected output, thermal lock or available queue capacity. Desktop reads horizontally. Following the first rendered review, phone puts the outcome immediately after selection, then its supporting constraints and calculation. Native radio controls and CSS-selected static panels work without JavaScript. An optional script announces the complete decision and runs a short gate transition; reduced motion skips it. State distinctions use words, values and geometry as well as color.

Evidence boundary: `/system/strategy` admission, not an entire workload's execution. Configured time estimates, mock engine response, forced queue/thermal states. Physical GPU swapping, actual temperature and benchmarks are unverified. No global portfolio redesign or publication.

Acceptance: exact route outcomes/provenance, screenshots at 1440/1280/768/390/320, keyboard/touch, no JS, blocked enhancement, reduced motion, 200% text, axe and no overflow, existing Observer/flagship checks, diff review. The selected direction is already authorized by the task; the design skill's multi-direction research/approval workflow is superseded by this bounded brief.
