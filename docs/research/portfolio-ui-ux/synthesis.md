# Synthesis: high-signal engineering portfolios

## Evidence-weighted principles

1. **Orientation beats atmosphere in the first viewport.** A visitor should understand the practitioner, demonstrated problem space, strongest work, and next action without decoding a visual metaphor. Current portfolio guidance repeatedly favors role, scope, challenge, and limits early; the conclusion is our synthesis, not a universal timing claim.
2. **Depth beats breadth when the evidence supports it.** Feature a small set of projects, with a clear maturity/evidence label and a direct source or case-study route. The UXfolio survey-based guide and several firsthand examples agree; no source proves a universal project count.
3. **The case study is an interface.** Give skimmers a summary, headings, captions, and anchor navigation; give evaluators decisions, artifacts, verification, limits, and next steps. A long linear narrative alone asks too much of a time-constrained reviewer.
4. **Artifacts are evidence, not wallpaper.** A real screen, source-derived diagram, test output, or process photo should answer a reader question and be captioned. Conceptual images are valid when labeled as such. Do not manufacture screenshots or metrics to fill visual space.
5. **Type, grid, and spacing are system behavior.** Use a restrained type palette, readable measure, fluid bounds, and spacing tokens. Specify what reflows, wraps, or stacks; avoid a desktop screenshot becoming the only truth.
6. **Accessibility is part of the credibility claim.** Semantic order, keyboard focus, visible focus, target sizing, zoom/reflow, contrast, and motion preferences belong in design decisions and QA—not an end-stage polish pass.
7. **Motion earns its cost by explaining something.** Use it for feedback, orientation, or relationships. The static/no-JS/reduced-motion experience must retain the same information and route.
8. **A portfolio should expose engineering judgment.** Show constraints, trade-offs, test boundaries, and unknowns. A polished outcome with hidden authorship or evidence level is weaker than a candid, well-structured prototype.
9. **QA is an iteration loop, not a final screenshot.** Evaluate real pages and capture representative widths, long content, focus, reduced motion, no-JS, blocked assets, and text enlargement. Use results to change the system rule, not to patch one viewport.

## Productive disagreements

| Tension                                           | Appropriate choice                                                                                                                                                       |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fast skim vs. deep explanation                    | Use a one-screen orientation plus anchors and expandable/deeper evidence. Do not make every visitor read the same long path.                                             |
| Strong visual identity vs. neutral restraint      | Let type, color, and one coherent visual motif create recall. Reduce decoration whenever it competes with project evidence.                                              |
| Real product screenshots vs. diagrams             | Use real approved screens where they prove behavior. Use source-derived diagrams for systems or confidential work; label conceptual diagrams.                            |
| Portfolio analytics vs. privacy/minimal requests  | Feedback can guide iteration, but this repository’s no-tracker posture remains valid. Prefer invited review and QA evidence unless analytics are explicitly authorized.  |
| Design-system consistency vs. project distinction | Keep shared navigation, type, spacing, and accessibility rules. Differentiate projects through evidence, imagery, and content hierarchy—not a new site skin per project. |

## Anti-patterns

- Vague “AI/innovation” claims, fake terminal/dashboard imagery, decorative code, or invented outcome numbers.
- One equal-weight grid that hides flagship work, role, evidence, and maturity.
- Tiny mono paragraphs, excessive all-caps labels, ornamental rules that outnumber content signals, or display type used as body text.
- Scroll hijacking, autoplay, perpetual motion, hover-only explanation, invisible initial content, and motion with no reduced-motion equivalent.
- Handoff by pixel coordinate instead of token, content, and reflow behavior.
