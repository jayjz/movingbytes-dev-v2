Systems · Glossary

The Economic Gatekeeper

Control Plane

A pre-execution filter that evaluates agent strategy proposals against a resource cost model. It rejects "doomed" strategies (high token count, low probability of success) before a single inference token is burned.

Why it matters: Prevents runaway compute costs and protects the GPU from "thrashing" on impossible tasks.
Applied in: AetherForge

VRAM Circuit Breaker

Resource Guardrail

A hard kill-switch triggered when GPU VRAM usage exceeds a safety threshold (e.g., 85%). Unlike soft throttling, this immediately aborts the current generation pipeline to prevent system OOM (Out of Memory).

Why it matters: Ensures the host OS remains responsive and prevents data corruption during high-load inference.
Applied in: AetherForge

Barge-in FSM

Edge Audio

A Finite State Machine designed to handle user interruptions ("barge-ins") during audio playback. It instantly truncates the audio buffer and transitions the system back to "Listening" state without context corruption.

Why it matters: Makes local voice agents feel natural and responsive, rather than forcing the user to wait for the machine to finish speaking.
Applied in: Unhinged Agent

Offline-First Fallback

Resilience

An architecture pattern where the local state is the "source of truth." Network sync is treated as an asynchronous bonus. If connectivity drops, the user workflow is uninterrupted; actions are queued for later sync.

Why it matters: Critical for field operations (HVAC, construction) where cellular signal is unreliable. Prevents "spinner of death" UX.
Applied in: HVAC Ops

01 Control Plane · Active

AetherForge

Hardware-aware safety and control plane for local AI agents on consumer GPUs.

Problem

Local agents on 8–16 GB cards fail predictably: runaway generation, context blow-ups, thermal stress, and strategy thrash that OOM the only GPU available.

Approach

FastAPI control plane with Economic Gatekeeper, thermal/VRAM circuit breakers (503), context ceilings (413), tool discovery, and durable audit logs. Agents negotiate strategy; the plane can refuse unsafe work.

Status

Wedge A verified under Mock engine (CI + no-GPU path). Real Fast-Swap / KV survival on 8 GB remains gated research (Wedge B). No production claim for unproven swap behavior.

THE ANTI-MANIFESTO

What I refuse to build.

A systems architect is defined by their boundaries. I don't ship vaporware. I build systems that survive the messy reality of physical operations and hardware limits.

01

I refuse to ignore physical constraints.

I do not build cloud-dependent agent swarms that assume infinite compute and perfect 5G. If a system cannot degrade gracefully under an 8 GB VRAM budget, thermal throttling, or a cellular dead zone, it is a liability, not an architecture.

02

I refuse to automate irreversible actions.

In physical trades, an AI hallucinating a $2,000 compressor order or scrambling a dispatch queue is catastrophic. I build systems where agents propose and operators decide. Strict human-in-the-loop execution gates are mandatory.

03

I refuse to sell hype as production.

I state exactly what is verified and what is research. A mock-verified control plane with documented boundaries is infinitely more valuable to an engineering team than a fragile demo masquerading as a production-ready product.

04

Adversarial by Default

Defensive architecture is useless without offensive simulation. I build threat models based on real-world exploit toolkits, ensuring local agents can survive compromised environments.

05

Compliance as Code

Autonomous agents cannot bypass enterprise governance. I build automated compliance canaries that scan pipelines nightly, ensuring drift is caught before it reaches production.
